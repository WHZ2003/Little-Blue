# 大肥鱼共享偏好

用户在桌面或微信明确表达长期偏好后，先由独立分类器提出结构化修改，再由程序核对原话、支持范围和字段值，提交 SQLite 后生成回执。聊天模型的“记住了”不是写入结果。

## 当前支持

- 对话偏好：称呼、语言、语气、回复长短、喜欢/不喜欢的事物、避免用语。两端每轮读取共同记录，用于生成回复；不能保证每句措辞完全符合，也不赋予新能力。
- 实际格式：`message_mode`（smart、whole、split_short）、`short_limit`（10～200 字）、`long_form_mode`（whole、split）。微信发送器与桌面气泡都消费这些值。
- 本地视频清理：`auto_close_video_tabs`。只对 B 站视频插件本次创建、未被用户接管的标签页生效；视频播放结束或退出观看后关闭，暂停时保留。用户旧页、新开的其他页、接管后的页、重启前无法确认归属的页均保留。云端及 surfing 字幕阅读不开可见网页。开关关闭时不自动清理；标签页归属限制始终不可关闭。
- 微信主动联系：开关、最小间隔（1～1440 分钟）、每小时上限（0～12）。写入真实 Settings，与原设置面板一致；不改变桌面自身的活动调度，不保证定时送达，仍遵守勿扰与可用会话限制。

例子：“以后叫我小丹，回答简短一点”“以后长文整条发，短聊天分条”“微信主动消息至少间隔两小时，每小时最多一次”。

“查看偏好”或 `/preferences` 查看保存值、云端版本、本地确认版本和待处理数；“撤销上次偏好”或 `/preferences undo` 恢复最近一次修改之前的值。明确要求恢复某项默认也可处理。恢复默认保留版本标记，旧离线消息不能重新覆盖它。

## 结果与限制

程序区分已写入实际设置、已保存为对话指导、暂不支持、需要澄清、失败与待同步。诸如自动打电话、任意定时任务、语音模型、放宽权限等没有对应受支持执行接口的请求，不能伪装成已生效的设置。模糊数字（如“主动消息少一点”）不得猜成数字或重置；数字和重置请求还要经过程序对原话的独立检查。

自然语言识别仍可能漏判。没有本轮保存回执时，不得把写笔记、旧聊天或模型口头承诺当成已成功；桌面提供 `shared_preferences_apply` 从当前真实用户事件补处理，工具不接受模型自造的设置或来源。一般闲聊不会因为出现关键词就成为偏好。

## 同步与持久化

云端主数据库新增 `shared_preferences`、`preference_history`、`preference_receipts`、`preference_pending`。保存原话引用、来源、来源时间、版本和处理回执；修改不覆盖聊天原文、人设卡或既有记忆。请求以真实消息编号或桌面事件游标去重，重试不会重复执行。每项按来源时间检查，较早的离线请求不能覆盖较新的偏好或设置面板修改。

桌面在模型回复前通过已认证 SSH 传输调用 `/companion/shared-preferences`。两端使用同一个云端记录；本地缓存于现有 `data/dafeiyu-sync.json`，可读副本位于 `workspace/shared/PREFERENCES.json`。五秒同步携带版本确认；本地先持久保存再确认版本。每次真实用户输入还会刷新偏好，并注入本轮上下文。

离线桌面先保存原始事件到本地待同步队列，明确表示云端结果尚未确认，重连后按原事件补处理。云端关闭联网时保存待处理请求，恢复联网、空闲时补处理，每条最多八次后台尝试、间隔至少十分钟；失败不会伪报成功。网络超时可能发生在云端提交之后，故回执使用“结果未确认”，以去重重试核对真实结果。

桌面偏好回执直接写入聊天记录，气泡也使用同一份程序回执；不能被模型改写成无依据的成功承诺。已写入的回执不会因模型选择不说话而丢失。对话偏好在每轮上下文里使用，格式设置在发送时读取，因此不依赖检索恰好命中某条旧记忆。

## 维护

历史偏好可用 `python -m tools.import_historical_preferences <数据库> <已人工核对的清单>` 预检，确认备份后加 `--apply` 导入。此工具只用于维护，不交给聊天模型：逐项核对数据库里的用户原文、消息编号和原始时间，核对预期版本，并在单一事务内写入偏好、历史和回执；不回放聊天，不写运行 Settings。相同清单重复执行不重复导入，旧来源不能覆盖更新的记录。兴趣等合并值需要人工结合上下文审核，程序不能验证语义概括是否正确。
