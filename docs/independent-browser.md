# 独立浏览器

用户明确要求「现在逛一次并分享」时，可通过已认证核心 RPC 调用 `op=browser, browser_action=share_now`，返回任务 ID；结果由 `/state` 中对应任务跟踪。该入口真实浏览后沿用分享生成、iLink 发送及确认落库流程，只跳过本次随机抽样和主动交流冷却，不修改日常设置。仍要求浏览器为自主模式、联网与分享开启、iLink 会话有效；勿扰、接管、聊天中断与发送失败不重试规则保留。不会自动重放重启前的请求，也不会将失败发送记成成功经历。

Docker 新增 `browser` 服务：非 root Chromium、独立 `browser-data` 数据卷、独立认证密钥；不挂载核心数据库、DeepSeek Key、微信账号或宿主用户目录。核心通过内部认证接口调度，Windows 桌面角色仍由原 PySide6 进程绘制。

## 使用

运行 `start-core.ps1` 构建并启动核心与浏览器。桌宠右键或托盘菜单 → **她的浏览器…**；已有旧桌面进程需重启才能显示新菜单，也可直接运行 `browser.ps1` 打开。入口使用 60 秒内一次性票据，进入后地址清除票据，HttpOnly / SameSite 会话有效 12 小时，过期后从桌宠重新打开。端口只绑定本机 `127.0.0.1:8766`，不要转发到公网。

查看页每约两秒显示浏览器真实截图，不读取用户电脑屏幕。三个模式：

- **让她自己逛**：允许生命系统在条件合适时自主浏览，不代表马上开始。
- **我来接管**：立即撤销旧自主操作，可点击截图、滚动、打开获准 URL 和返回上一页。
- **暂停**：停止当前浏览，保留页面。关闭查看页不改变模式。

每次浏览器重启默认暂停；由用户重新选择自主浏览，不恢复未完成任务。微信 `/browser` 查看状态，`/browser pause` 暂停，`/browser auto` 允许自主浏览；这些是明确的本地控制命令，不交给模型判断权限。查看和接管入口需在电脑上打开。

## 自主活动

核心启动至少 60 秒，最近 90 秒没有用户消息，联网开启、不在勿扰／专注／聊天时，好奇或无聊达到阈值，才可能开始；平静时也可每两小时尝试一次。精力不足、睡觉或被拖动时不浏览。每次最长 60 秒、最多两页，尝试间隔至少 20 分钟、滚动每小时最多两次、24 小时最多八次；次数在 SQLite 保存，重启不清零。模型最多调用一次，按页面实际链接和内部状态决定继续看什么或休息，沿用已有每日 API 请求／Token 预算。

用户聊天或接管时取消当前探索；所有操作带版本，接管后的旧请求和取消不能覆盖用户的新操作。失败不自动重试，已成功阅读的页面可保留。浏览活动不直接发送微信，实际经历进入原 SQLite episodic 记忆、向量索引与认知上下文，是否分享仍由原主动交流门控决定。

## 实际内容与边界

### 偶尔把有趣的内容分享给你

成功阅读后进入独立分享候选，不是每次浏览都发送。约一半候选直接留给她自己，剩下的交给模型判断是否有趣，模型仍可沉默。最多每天两次评估、间隔至少两小时，继续遵守主动交流总开关、勿扰、聊天空闲和 API 预算。候选超过一小时、已处理或遇到新聊天后过时，不补发。

首版是一两句自然聊天加代码附上的真实来源链接；链接来自阅读记录，模型不能改写 URL。没有截取或发送用户电脑屏幕；尚未加入网页截图附件。只有微信确认发送成功，才把这次分享记为已发送。普通主动聊天不重复汇报浏览记录。

微信 `/sharing off` 关闭网页分享，`/sharing on` 恢复；关闭主动交流也会停止分享。当前使用现有 iLink，Windows 桥接通过验证后可由同一事件队列交给新通道发送，且仅发送给已确认的主人私聊，不主动投递到群。

第一版只开放 `wikipedia.org`、`wikimedia.org`、`nasa.gov`、`noaa.gov` 及其子域的 HTTPS 公共内容。所有页面和资源请求验证域名及公共地址，仅允许 GET / HEAD，阻止音视频、WebSocket、service worker、下载和额外标签页。不支持账号登录、输入表单、上传文件、发表内容或观看视频。接管同样遵守网站范围；它是阅读浏览器，不是完整虚拟桌面。

经历保存实际读取的页面标题、URL、UTC 获取时间和有界原文摘录；HTTP 错误、取消和空页面不作为阅读完成证据。网页内容标注为不可信资料，不生成用户偏好、不改变人格或成长身份卡；引用网页不等于独立核实其中的事实。

Chromium 显式开启 sandbox，Docker 限制进程数、CPU、内存、只读根目录、无额外 capabilities。使用 Playwright 官方 seccomp 配置允许非 root 用户命名空间。域名范围、应用验证和容器是多层限制，不是对任意恶意网页的完整安全承诺；不开放任意站点或宿主文件。

## 文件来源

`browser_service/seccomp_profile.json` 来自 Microsoft Playwright 的 `utils/docker/seccomp_profile.json`（2026-10-21 获取），保留 `browser_service/PLAYWRIGHT-LICENSE.txt`。本地增加 `chroot` syscall 许可，使 Chromium 在容器 capabilities 全部移除时仍能在自己的用户命名空间内建立沙箱；没有增加宿主权限。浏览服务和查看页为本项目实现，直接使用 Playwright Python API，没有引入完整 Harness 运行时或改动既有人格。

真实页面截图通过独立会话保护，访问日志关闭以免记录入口票据。浏览器数据只在专属卷中持久化。核心停止不会自动关闭浏览器服务，可在查看页暂停或执行 `docker compose stop browser`。
