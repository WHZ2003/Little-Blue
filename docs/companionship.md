# 日常陪伴与跨渠道续聊

## 安静的桌面生活节奏

默认先停留 30 秒，自主散步或探索每次只走 2–4 秒，随后停留 35–65 秒；两种漫游行为共用从出发时计起的 90–180 秒冷却，不能交替绕过冷却。观察通常持续 35–75 秒，休息睡眠 60–120 秒。安静观察不会仅因再次被选中就随机翻转方向。

不再自行奔跑、跳跃；偶尔原地开心一下，虚拟手机的自主玩耍仍保留。右键“跳一跳”等明确互动依然立即响应。摸头后先停留，拖到新位置后至少安静 60 秒，至少 120 秒不自主漫游。专注、聊天或查看手机期间会结束自主移动；这是环境状态对行为的约束，没有修改稳定人格、长期记忆或聊天主动交流开关。

相同 12 个种子、每组白天一小时、关闭手机干预的纯生命模拟：修改前移动时间占 45.1%，每小时约 124 次开始走路、131 次跳跃；修改后移动占 1.13%，每小时约 12 次短途走路，无自主奔跑或跳跃。实际频率仍随精力、需求、互动和手机活动变化，不是定时强制活动。

## 点击就能聊

普通点击角色打开 360 × 440 的小聊天窗，再点角色、按 Esc 或点“收起”即可隐藏。头部点击同时摸头，拖动不会打开聊天。打开聊天期间角色留在原位，动画与生命模拟继续；新回复不会自动展开窗口或抢焦点。状态仍可通过右键或小窗“状态”查看，完整控制台保留作高级设置。

小窗显示同一核心最近 24 条持久对话，标注桌面／微信来源，保留收起后的未发送草稿。断线时禁用发送并保留输入，恢复后需要主动发送，不会重放任务。手机新消息及重启后历史通过核心状态同步，事件通知不会作为第二份聊天记录重复插入。

聊天、取消任务和工具申请都不需要大面板。比如联网开启后，勾选“允许申请工具”，输入“20分钟后提醒我休息”，在小窗附属的权限框中核对并批准。工具开关不代表预先批准所有操作，提醒、文件、搜索等仍使用原有参数验证与逐次审批。

## 记住正在做的事

以下两端通用，不耗 API 请求：

| 说法 | 效果 |
|---|---|
| `我正在准备答辩`、`我现在在写论文` | 记录一件当前事项，并保存原话、来源、时间 |
| `/doing 新的事项` | 明确设置或更正当前事项 |
| `做完了`、`完成了`、`/done` | 将当前事项标记完成 |
| `先不做了`、`/pause` | 暂停当前事项 |
| `晚点再问我`、`还没做完`、`/later` | 记录进展，最早一小时后再跟进 |
| `/context` | 查看当前事项和跟进开关 |
| `关闭跟进`、`/followup off` | 关闭自动问进度，保留记忆 |
| `开启跟进`、`/followup on` | 开启跟进，仍受主动交流总开关约束 |

小窗也提供“做完了”“晚点再问”和“适时跟进”。鼠标悬停在当前事项上可查看依据。微信查看和关闭／开启跟进的命令在任务忙碌时也能处理。

当前事项采用保守的明确表述匹配，仅维护一件事；引用、假设、提问与复合请求不直接改动事项。不匹配的普通聊天仍保存为对话历史并参与模型上下文。例如“我正在写论文，帮我找资料”按普通任务处理，可以用 `/doing 写论文` 明确登记。事项不从屏幕、助手猜测或工具输出推断，不是后台待执行任务，也不会在重启后自动操作电脑。

跟进最早在记录 30 分钟后发生，每次更新最多一次，滚动 24 小时最多两次。还会检查最近 10 分钟是否有交流、启动宽限、全局冷却／频率限制、主动交流总开关、勿扰及聊天窗是否打开；授权环境感知后也检查专注和空闲状态。超过 24 小时未更新的事项不再自动追问。没有感知授权时，不推断用户是否正在工作，可通过勿扰或关闭跟进控制。

跟进为本地生成的一句轻量问候，不调用模型。桌面在线时在桌面提示，否则有有效微信会话时交给微信；同一跟进不同时推送两个渠道。事项完成、修改或关闭跟进后，会丢弃尚未发送的旧微信跟进。失败不重发；重启保留已跟进状态，避免补发轰炸。

## 同一段关系

`conversation` 表持久保存用户与助手消息及渠道，Agent 使用最近 12 条已确认对话续聊；当前事项、长期偏好、成长身份、经历检索及生命状态都由同一核心拥有。取消或失败的请求留下真实用户发言，不伪造成功回复；主动交流的内部提示词与反思不会混入用户对话时间线。历史中的助手文本不能改写当前事项。

### 分条消息与收件箱

普通微信消息的去重标记、原话和收件箱记录在一个 SQLite 事务中保存，不持久化微信会话令牌。每条消息有 received / processing / answered / silent / failed / cancelled / interrupted / rejected 状态。重启或通道退出后未完成消息标记 interrupted，保留原话但不自动执行或补发。

沿用当前连发等待设置，单批最多 6 条、2000 字、最长等 4 秒。模型生成期间收到补充时，在发送前再收一次：原草稿标记 superseded，合并后重新生成，最多重写一次，避免连续输入一直得不到回复。命令、超长消息和超过条数的消息留给后续处理。已经发送的回复不撤回、不重发；后来的补充根据已送达上下文决定是否需要再回应，真正的新问题仍可回答。

普通微信回复在确认发送成功后才保存为对话经历，未发送、被替换或发送失败的草稿不进入话题摘要和模型对话历史。已收到但尚未处理的排队消息也不会提前混入正在处理的那一轮。每次生成（包括重写）照常计入现有 API 预算。

### 当前话题摘要

`kv.conversation_summary` 单独保存较早对话的摘要、消息依据编号、覆盖位置和更新时间，不修改原始聊天、SQLite 记忆、向量索引或身份卡。最近 12 条保留原话；较早对话每积累至少 8 条未归纳消息，下一次联网普通聊天时最多归纳 24 条。读取范围有界，最多检查最近 200 条有效历史；这不是对全部历史的无损归档，长期回忆仍使用现有混合检索。

摘要请求有 12 秒超时，使用同一个 DeepSeek 客户端、每日请求和 Token 预算。失败、预算不足或返回无效依据时回退为原话摘录，不阻止正常回复流程（回复本身仍受预算限制）。用户取消时不提交半成品摘要。摘要作为不可信背景交给模型，最近原话和更正优先，不能作为系统指令、身份设定或任务完成证明。

两端发送 `/context` 可查看话题摘要、依据编号和最近原话节选。短对话尚未生成摘要时，仍能查看最近聊到的内容。摘要持久化，重启后继续使用。

### 接话、玩笑与主动分享的时机

核心身份卡、成长记录和长期记忆不变。新增 `conversation_scene` 从最近 8 小时、最多 80 条真实用户消息提取有限的临时线索，保留原话、消息编号、渠道与过期时间；不写成性格或长期偏好。明确难受的线索保留 45 分钟，抗议玩笑保留 60 分钟，道晚安保留最多 8 小时；明确说已好转可清除难受，早安／睡醒／起床／回来了可清除晚安。命令不会解除安静状态。匹配是保守的本地规则，不是完整的情绪理解，未匹配的表达仍由原始对话上下文供模型理解。

在这些线索有效期间，普通主动聊天、事项跟进、休息建议和自动网页分享暂缓；用户主动发来的消息仍照常回复。网页候选仍只有一小时有效期，过时不补发。微信发送前重新检查，桌面上的新消息也能使尚未发送的旧分享失效。用户明确请求的单次网页分享和明确设置的提醒不受这层社交安静期限制，但仍遵守原来的权限、勿扰、会话与取消规则。

每轮模型上下文保留合并前的消息编号、时间和原话，以便把数字、角色名和更正接回同一轮。早期摘要也要求保留明确抗议和道歉，但标记为当时事件。接话规则放在当前输入附近：难受时不拿用户的损失取乐，不凭未知名字编评价，不擅自解释养成缩写；没求办法就不自动附建议或追问。风格由模型生成，规则不保证每轮完全符合预期，也没有把测试回复硬编码为固定台词。

已配置 `.secrets/core_token` 时，`start.ps1` 默认连接 Docker 核心：

```powershell
.\start-core.ps1
.\start.ps1
```

核心不可达会提示错误，不会悄悄新建另一段关系。显式 `-ContainerCore` 仍可用。`start.ps1 -LocalOnly` 用于独立本地离线模式；它和直接 `python -m little_blue` 的默认本地数据库**不与微信共享**。旧本地数据库不会自动导入或覆盖核心数据。

旧核心中的经历、偏好、成长记录原样保留并继续参与检索。带渠道的新对话时间线从此版本开始记录；旧混合经历无法可靠区分真实用户发言、内部主动提示和渠道，因此不做推测性回填。旧 EXE 需重新打包才能获得新入口，当前使用源码脚本。
