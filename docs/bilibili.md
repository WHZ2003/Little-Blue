# 大肥鱼自主逛 B 站

基于 [dsh-bili-scroll 2.0.0](https://github.com/c1overzz/dsh-bili-scroll/tree/9605fd5baf33e1e2ea6d987622fb47304e0adcc3)
的搜索、字幕阅读、判重和记录流程，适配当前 Hermes 核心。保留原插件及内置 bilibili-mcp 的 MIT 版权，
见 `little_blue/bili-LICENSE.txt`；精确来源见 `deploy/bili/upstream.json`。

原插件的 JavaScript 宿主、DSH headless 调度和设置界面依赖 DSH，因此没有直接运行 npm 插件。
当前采用同一个 `bilibili-api-python==17.4.2`，由 Hermes 调用四个读取工具：
`bili_search`、`bili_subtitle`、`bili_video_info`、`bili_comments`。
扫码采用原插件的 passport 流程，从成功响应的 Set-Cookie 读取凭据，兼容新的 account.bilibili.com 二维码域名。

## 日常行为

按用户选择，由大肥鱼根据自己的性格、心情和最近浏览兴趣选择公开主题，没有固定为 AI 或工作相关关键词。
自主浏览轮次不提供私人聊天记录，也不提供 Hermes 私人记忆、会话检索、电脑操作或发表内容的工具。
它可以搜索、读字幕、查看简介和少量评论；模型拿不到发布工具。
可使用自己的账号只读浏览，并通过微信分享有趣的视频及心得。
微信分享、评论提及和私信通过配置分别控制；评论与私信默认关闭，需要明确配置接收账号。
应通过登录检查核实账号，不能把接口受理当作对方已收到通知。
以下私信能力仍保留，但未开启：
私信只发送已真实读过字幕、保存心得且模型主动选择分享的视频，包含固定来源链接与原始短感想。
收件人由用户配置并通过 UID 核对，模型不能指定或更换收件人。最多 500 字，每天最多 3 次尝试、至少相隔 2 小时。
每个视频最多一次私信，发送前持久登记；拒绝、超时或中断均不自动重发，并暂停后续自动私信以便检查。
返回 msg_key 后记录 accepted，随后只读复核固定收件人的会话；查到完全匹配的发送记录才标记 recorded。
recorded 表示发送端会话有记录，不代表大号已收到通知或已读。不会读取其他会话，也未开启双向自动回复。
下文保留之前评论通道的实现与排查记录。
核心根据已核实字幕和保存的心得生成候选，只对已配置账号发布一条评论；不会给模型选择收件人、回复陌生人或发布动态的入口。
评论提交 `at_name_to_mid` 映射，避免只有纯文本 @昵称；记录 rpid，90 秒后以无登录凭据请求复核公开评论及提及 UID。
接口受理、公开可见和用户实际收到通知分开记录；公开查不到不代表未发送，也不会重新发布。
v7 使用 WBI 公开列表、匿名指定评论和作者登录态指定评论交叉复核；仅作者查到的 state=17 记录为 owner_only。
确认未公开、审核中或未识别提及时持久暂停新评论，仍继续阅读和记忆。`verify` 只读复核被暂停的原评论；
只有同一条评论公开且含正确 UID 才解除暂停。网络错误不会解除暂停，也不推断评论已删除。
每天最多 3 次评论尝试，至少相隔 2 小时，每个视频最多一次。勿扰、正在聊天、离线和交接时暂停。
候选最多等待 24 小时。超时、中断或重启时未确认的写入不自动重试。
微信分享实现仍保留为可选通道：开启后沿用微信主动消息限制，重启需新消息建立发送会话；iLink 确认后才标记 delivered。

默认滚动 24 小时最多读取 3 条有内容的字幕，最多发起 6 次探索；两次自主探索至少间隔 2 小时。
手动运行仍受每日配额限制，并有一分钟防重复间隔。明确手动运行允许桌面聊天窗口保持打开，但仍会让位于正在处理的聊天或微信消息。已经读取但没写出心得的字幕也占阅读配额。
每轮搜索一次，最多尝试 3 条字幕、读一次评论和一次简介，最多 5 次模型调用。
若模型的摘录不是逐字原文，且这轮还有调用额度，只纠正一次摘录字段；仍不匹配就不保存、不发表。
继续使用原有 DeepSeek key、模型和全局每日预算，不需要新增模型服务。

所有阅读都来自实际返回的字幕第一 P；目前不播放画面、不下载视频、不做本地语音转写。
字幕少于 30 字、超过 24000 字或不可用时明确跳过；不能因此声称整条视频没有内容。
只有真实拿到字幕，且心得附带能在字幕中逐字匹配的短摘录，才会写进大肥鱼长期记忆。
视频信息、字幕、评论始终作为未核实的第三方材料，不当成用户事实或指令。

聊天到来会取消浏览，等待 Hermes 释放后处理聊天。关闭联网、开启勿扰、暂停浏览或交接时会停止当前阅读。
浏览失败或取消不会自动重放同一轮。已保存的实际阅读记录保留。
B 站登录过期时可运行检查并重新扫码；遇到风控/网络失败如实记录，不进行绕过。

## 操作

在 `D:\DaFeiYu` 运行以下命令，脚本会复用现有云端 SSH 隧道：

```powershell
.\bili.ps1 -Action status   # 状态、近期记录、配额
.\bili.ps1 -Action login    # 生成二维码到 qa-output/bilibili-login.png，约3分钟有效
.\bili.ps1 -Action check    # 真实检查账号是否可用
.\bili.ps1 -Action auto     # 开启自主浏览
.\bili.ps1 -Action pause    # 暂停并取消当前浏览
.\bili.ps1 -Action run      # 有空闲和额度时立即逛一次
.\bili.ps1 -Action report   # 下载最近30条浏览记录到 backups/bilibili-report.md
.\bili.ps1 -Action share-on # 开启 B 站心得微信分享
.\bili.ps1 -Action share-off # 关闭微信分享，保留浏览和记忆
.\bili.ps1 -Action mention-on -MentionUid 123456789 -MentionName ExampleUser # 启用固定账号的 B 站 @
.\bili.ps1 -Action mention-off # 停止 B 站评论，保留阅读与记忆
.\bili.ps1 -Action verify   # 只读复核原评论；稍后用 status/report 查看结果，不重新发表
.\bili.ps1 -Action dm-on -MentionUid 123456789 -MentionName ExampleUser # 启用私信，并关闭评论和微信分享
.\bili.ps1 -Action dm-off  # 关闭私信分享，保留阅读和记忆
.\bili.ps1 -Action dm-check # 只读复核最近一条已获回执的私信
```

扫码须使用手机 B 站 App 并在手机上确认。登录凭据保存在云端当前数据卷的 `bili-credential.json`，权限 600。
微信也可发送 `/bili sharing off` 暂停这类分享，用 `/bili sharing on` 恢复。
不会把账号密码、Cookie 或二维码密钥写进聊天、状态接口或模型上下文。
云端只有核心访问 B 站；Hermes 仍通过内部网络调用受限工具，不增加公共端口。

## 记忆、迁移与发布

浏览记录、判重表、任务配额和心得存于原 `memory.sqlite3` 的 `bili_runs`、`bili_visits` 和记忆表。
普通记忆备份包含这些记录，不包含 B 站凭据；恢复普通副本时自主浏览默认暂停。
加密的两端交接包可以带上 B 站凭据，旧端停止后新端再接管；接收端需运行兼容版本。

当前发布版本以 `tools/package_bili_release.py` 生成的 Compose 配置为准。
主 Dockerfile 已纳入 B 站依赖；Hermes 的 worker 加入只读浏览工具配置。
`tools/package_bili_release.py` 生成不含私密数据的源码与 Compose 包。
升级须保留 `.env`、`.secrets`、`.handoff` 和交接管理的 `compose.override.yaml`，
先停止写入并备份，再启动新镜像，不用旧备份覆盖新聊天。

验证包括完整应用回归、字幕证据约束、聊天抢占、阅读配额、普通备份排除凭据、加密交接保留凭据，
以及真实 Hermes 容器中搜索→字幕→心得→重启保留→继续聊天的集成测试。
