# DeepSeek 的微信聊天通道

已支持发送图片表情：`/memes` 查看，`/meme 087` 点发，`/memes off` 关闭自动配图；见 [表情包说明](memes.md)。接收端支持文字和图片；语音和文件仍未接入。

微信图片通过白名单 CDN 下载、AES 解密，再用现有 `deepseek-flash` 识别（[官方视觉文档](https://api-docs.deepseek.com/guides/vision/)）。识别摘要带明确标注写入这条来信，随后交给原有聊天流程，保留人设、记忆和短消息规则。每条来信最多三张图、每张下载最多 8 MiB／2000 万像素；识别前缩至最长边 1600 像素并去除元数据，只读取动图第一帧。图片与解密凭据只在内存中处理，不保存原文件。每条含图来信增加一次有预算约束的识别调用；内联图片按每张 4096 token 保守预留，成功后以实际用量结算，不把 base64 字节误算为文字 token。失败不猜图、不自动重发；取消会中止正在进行的识别。

身份成长控制：发送 `/identity` 查看两层身份卡，`/identity 版本号` 查看引用的记忆依据，`/growth off` 或 `/growth on` 关闭／开启自动成长，`/growth undo` 撤销最近更新。命令不调用模型，也不作为学习来源；关闭保留已有设定。详见 [角色身份](character.md)。

通过腾讯 ClawBot / iLink 接入个人微信，收发代码运行在现有 Docker 核心中。使用当前核心的 Agent、需求状态、预算和 SQLite 记忆，不运行第二套 OpenClaw。当前支持文字和图片私聊、状态查询、取消微信任务以及受限的主动通知；语音、文件和群聊尚未接入。

协议依据：腾讯 [openclaw-weixin 协议文档](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)、[扫码流程](https://github.com/Tencent/openclaw-weixin/blob/main/src/auth/login-qr.ts)及[文本消息实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts)。这是独立 Python 实现，没有复制或安装上游插件。客户端协议不代表服务器保证，账号是否可绑定以及主动消息是否能送达需实测。

## 启动和绑定

在项目目录的 PowerShell 中运行：

```powershell
.\start-core.ps1
.\start.ps1 -ContainerCore
```

另开项目目录的 PowerShell，运行：

```powershell
.\wechat.ps1
```

用自己的微信扫描终端二维码，并在手机确认绑定；若手机要求配对码，在该终端输入。二维码等待上限约 5 分钟，过期后重新运行命令。腾讯的 [CodeBuddy 接入示例](https://cloud.tencent.com/document/product/1831/137450)要求微信至少 8.0.70；实际以你的微信账号所展示的入口和授权流程为准。

扫码成功后，在微信对应的 ClawBot 会话发 `/status`，应收到 DeepSeek 的精力、心情与联网状态。微信中显示的机器人名称由微信端控制，本项目没有宣称能够改写平台会话名称。

普通文字会进入当前核心的聊天和记忆。默认联网关闭时回复离线陪伴文字；需要 DeepSeek 对话时，右键桌宠 → 控制台 → 设置 → 启用联网认知。密钥由 Compose 从项目 `.env` 注入，微信消息及相关记忆会在联网开启时发送给 DeepSeek。无需把密钥发到微信或 Codex。

## 管理

### 连发消息与选择不回复

普通文字先保存到共享对话，再等待约 **1.2 秒**看是否还有补充，一起理解。一次合并最多等待 4 秒、最多 6 条／2000 字；达到边界后继续按顺序处理，命令单独处理。`wechat_batch_seconds` 可在核心设置中调整（0 表示不等待）。

如果第一条回复已回答后续补充，模型可以选择**记住但不回复**，不会另外发“收到”、空消息或表情；新的问题、请求和重要更正仍应回应。这是结合上下文的模型判断，不保证每次都准确，也仍消耗正常认知预算。明确单独发送“先不用回复”可以直接保持沉默。设置中的“微信允许记住但不回复”可关闭此策略，默认开启。

补充消息在前一条回答生成期间到达时，下轮也能看到刚刚确认送出的回复。失败或尚未确认送达的助手消息不作为已回复历史；未回复的用户消息仍进入共享记忆。取消清空待执行队列但保留已收到的对话记录；重启后不自动处理这些记录或重发草稿。

### 主动来找你

后台根据社交需求、无聊、当前事项决定是否交流；长时间没有联系时（约一小时）也有一次考虑交流的机会，模型可以选择保持沉默。不是每小时必发，也不承诺固定送达时间。默认主动交流间隔至少 15 分钟、每小时最多 3 次，遵守勿扰、专注、工作状态和预算；收到用户消息后的至少 90 秒不主动插话。新来信会使尚未发送的旧主动话题失效。

`/status` 现在显示联网、主动交流、勿扰、会话可用性、连发窗口和是否允许不回复。模型也会收到这些真实能力和状态，不应再声称“应用没有主动微信消息功能或开关”。核心重启后仍需先收到一条新消息取得会话，之后无需保持桌面窗口打开。

当前部署已按用户反馈调低为最少间隔 60 分钟、每小时最多 1 次（新安装默认值不变）。可在 Coopanion「大肥鱼共享记忆与微信 → 主动消息设置」直接修改并核对云端实际值，详见 [同步说明](companion-sync.md#主动消息设置)。

### API 预算和错误提示

`/status` 同时显示今日 API 请求次数和 Token 已用与预留量。联网开关打开仅代表允许联网，不代表预算、密钥和服务端一定可用。预算不足、密钥认证失败、服务端余额不足、限流和网络超时会给出不同的提示。

请求前仍按保守上界预留 Token，成功取得有效的 `usage` 后按实际 `prompt_tokens + completion_tokens` 结算；依据 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。缺失或无效的用量、超时和取消保留预留，避免把可能已发生的消耗清零。结算有持久票据防止重复退还，跨午夜结算记入请求开始那一天。旧版累计数据没有实际用量凭据，继续保留保守值，不伪造退款。

两项每日限额分别生效，达到任意一项都会阻止新请求；静默判断、主动交流、反思及成长也计入额度。额度按核心本地日期重置，当前 Docker 配置为 `America/New_York`。本次用户指定运行配置为 **200 次请求／200,000 Token 每日**，不改变新安装的默认限额。

```powershell
.\wechat.ps1 -Action status   # 仅显示绑定文件状态，不保证服务端在线
.\wechat.ps1 -Action disable  # 关闭收发，核心约 2 秒内停止通道
.\wechat.ps1 -Action enable   # 恢复已绑定通道
.\wechat.ps1 -Action logout   # 删除本机绑定凭据；手机端可另行解绑
```

点击桌宠的状态卡可查看核心返回的微信连接状态。微信 `/cancel` 只取消微信任务并清空待处理微信消息，不取消桌面发起的任务。桌面端仍可取消当前核心任务。

## 权限和运行边界

- 绑定操作授权回复扫码账号。固定接收人来自登录返回的账号标识；其他账号、群聊、机器人回声和撤回事件被忽略。不能由模型指定任意接收人。
- 微信端目前只聊天，不提供任何电脑工具，模型即使返回工具调用也会被拒绝。需要文件、浏览器或系统操作时，在桌面端发起并走既有 Permission Gateway。
- 来信 ID 先持久去重再进入最多 20 条的内存队列。崩溃前已经接收但未处理完的消息不会自动重放，用户可重新发送。桌面与微信共享单个 Agent，同一时刻只处理一个认知任务。
- 只转发主动交流结果和提醒，遵守勿扰、专注、主动交流总开关以及间隔/小时上限。自动通知在内存最多保留 20 条、最多 1 小时，不在重启后补发；提醒在核心记录中交付不等于微信已送达。
- 每次重启需先收到一条新微信消息，才能获得用于主动通知的会话 token。本实现额外限制其本地使用时间为 12 小时，这不是平台承诺的有效期。没有会话 token 时不发送；平台失效或拒绝时记录失败。
- 发送超时或结果不明不会自动重试，避免重复消息。读请求会退避重连；会话失效后等待重新绑定或显式恢复。日志不记录 token、配对码、账号 ID、消息正文或请求头。
- Docker 核心运行且通道可用时，微信聊天不依赖桌面窗口在线；关机或停止 Docker 后无法收发。未绑定时不启动任何微信轮询。
- 凭据原子写入命名卷 `/data/wechat-account.json`，Linux 权限为 0600，不进入源码、镜像、状态 API 或模型上下文。核心 HTTP 端口仍只映射到本机，不需要公网回调端口。

## 验证

测试覆盖出站固定接收人及上下文 token、跨重启去重、陌生账号拒绝、共享记忆、无桌面时聊天、取消、模型工具隔离、关闭通道、通知限频、扫码凭据保存及错误脱敏。测试使用模拟传输；真实收发只有在用户扫码并发送消息后才能确认。
# 日常续聊更新

桌面小聊天窗与微信共用持久对话、当前事项及长期记忆。桌面说“我正在准备答辩”，手机可接着聊或回复“做完了”；`/context` 查看事项，`/followup off` 关闭跟进，`/followup on` 开启。电脑操作仍只能在桌面发起并审批。启动桌面请用 `start.ps1`（存在核心令牌时默认连接 Docker）或 `start.ps1 -ContainerCore`，详见 [日常陪伴](companionship.md)。
