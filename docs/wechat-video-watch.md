# 微信发起电脑看视频

微信发送 B 站视频链接或含清晰 BV 号的截图，再说“看看这个”“打开这个视频”。在线桌面的 B 站插件空闲时，会新建自己的标签页并实际播放，微信依次收到提交、确认开始、完成或失败回执。截图本身只提供视频编号，图片里的文字不能授权电脑操作；多个候选或编号读不清时明确要求指定链接。截图与紧随其后的“看看这个”最多关联两分钟内最近一条微信用户消息。

当前执行器支持 B 站第一 P、时长不超过两小时的视频。短链接先经受限解析，再派发固定的 B 站视频 URL。不存在通用远程鼠标键盘、任意网址或脚本执行接口。明确要求“只读字幕”“总结”的请求仍可使用只读资料工具，但不能声称播放过画面；微信聊天生成端也对读字幕后的常见观看成功措辞做了拦截。

## 任务与结果

云端 `video_watch_jobs` 记录当前认证微信消息创建的任务，绑定配对桌面、当次桌面进程会话和随机任务令牌。桌面心跳需在 25 秒内且插件就绪；不在线就直接说明，不排队等未来开机。任务须在 45 秒内领取，领取后心跳租约为 90 秒。运行中的桌面失去同步超过 75 秒会停止自己的播放；整体任务至多三小时。

同步仅传递窄结构的 `video_watch` 字段。桌面先持久记录领取意图，取得云端领取确认后再持久记录“已开始执行”，然后才打开页面。同一请求与重复确认不会重复开视频；桌面重启生成新的进程会话，旧任务报告中断，不恢复播放。普通同步历史继续以 `deliver:false` 归档，不作为新指令执行。

“开始”须有播放器实际前进的进度。“完成”须有自然结束状态、接近视频结尾的位置、覆盖至少九成时长的连续播放进度，以及合理的墙钟时间；拖动进度条到结尾不能伪造看完。打不开、播放器受限、卡住、断线、用户接管和页面关闭均报告明确失败。回微信的是已核验的播放结果，不生成没有画面证据的内容感想。

B 站启动后可能恢复账号历史进度。执行器在最初五秒内最多两次归零重播，并清空此前的覆盖时长；超出启动窗口的跳转仍视为未完整播放。站点改写跟踪参数时，仅在同一页对象、归属仍有效、视频编号及分 P 未变的情况下刷新导航凭据；不能借此重新认领用户已接管的页面。

任务使用新的专用 Page 对象；不复用原页，不按 URL 认领页面。新任务不会抢占正在使用的视频插件。用户点击、输入或自行导航导致归属失效时停止任务，并保留页面。完成后遵守 `auto_close_video_tabs`；失败时只清理仍归自己管理的任务页。整个流程不关闭用户标签页、整个浏览器或浏览器进程。

微信发送“停止播放”“别看了”“取消观看”或 `/cancel` 可取消任务。电脑下一次同步后处理取消；断线时不能声称已经即时停止。

`video_watch_notices` 是结果发件箱，固定给原请求账号。发送前先落库认领，确认送达后才将消息标记为 delivered；结果不依赖主动聊天的频率开关。发送失败、超时或重启时的模糊结果不自动重发。微信服务重启后仍须收到该用户的新消息取得可用会话，结果最多等待十二小时。原聊天、记忆、日记和偏好不被迁移或重写。

## 安装和验证

云端需要 `little_blue/video_watch.py` 以及对应的 companion、wechat、cognition 集成。本地同步扩展需要 `video-watch.mjs`；视频插件先安装归属保护补丁，再运行 `python tools/patch_coopanion_video_watch.py --package .research/Coopanion/data/extensions/node_modules/cortico-world-bilibili-video`。应用空闲时通过自身接口重启并重载环境提示。

Windows 已安装便携应用及 Node.js 时，可运行 `./tools/test_coopanion_video.ps1 -BrowserSmoke`，在候选插件副本上应用补丁、执行同步与页面保护测试，并用独立无界面浏览器播放本地生成的片段。测试不修改正在运行的插件，不发送真实微信消息。

验证使用临时数据库和模拟微信：请求识别、配对校验、重复领取、断线/重启、失败状态、进度不足、一次性结果发送及既有同步功能。独立 Chromium 测试播放本地生成的真实 WebM 片段，通过同步中继领取后才打开，得到实际前进与结束回执，确认用户旧页保留，并验证真实点击接管后不关闭页面。没有往真实微信发送测试话术，也没有重放旧的截图请求。

另在独立浏览器实际播放用户提供的 B 站视频 BV1URHG6zEWq，核验 235.328 秒连续播放至自然结束、采集 45 次画面、仅关闭任务标签页。该测试不向微信发消息；微信消费者及回执发送使用模拟传输验证。
